# Lens Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An occam skill and mod, `lens`, that draws a json-render spec, custom HTML or Mermaid source as a picture inline in the Claude Code chat.

**Architecture:** One mod module in occam registers the deferred tool `mcp__occam__lens`. The tool fills a static page template with the source, opens it as a `file://` page in a per-session agent-browser, takes a screenshot of `#lens`, and returns the PNG to the model as an image block. A `ToolUse` render hook draws the same PNG bytes under the tool row with `Image`. No server: the page loads its libraries from esm.sh and jsDelivr through an import map.

**Tech Stack:** Claude Code mod API 2.1.322 (`register(on)`, `$`), plain Node for tests, agent-browser 0.41.0, React 19.2.0, @json-render/* 0.22.0, zod 4.1.12, Recharts 3.10.1, Mermaid 12.3.0, @tailwindcss/browser 4.1.17.

**Spec:** `docs/superpowers/specs/2026-11-11-lens-design.md`

## Evidence from the planning spikes (2026-11-11)

- Gate: `hooks/hooks.json` with both `"hooks"` and `"modules": ["./lens.ts"]` loads under `claude -p --plugin-dir .`. Debug log: `hooks module occam@inline loaded (worker …); events: session.start,tool.call`, and `razor-activate.js` (plugin occam@inline) ran. The probe tool returned `LENS_PROBE_OK`.
- A mod tool returns an image to the model with `{ result: [{ type: 'text', text }, { type: 'image', source: { type: 'base64', media_type: 'image/png', data } }] }`. `{ result: { content: [...] } }` fails validation; `{ type: 'image', data, mimeType }` is removed by the API ("Field required").
- A `file://` page with this import map rendered a shadcn `Card` and a Recharts `BarChart` in dark mode, no server, no transpile. `defineRegistry(catalog, …)` is required: raw `shadcnComponents` in the registry fail ("reading 'maxWidth'"). Externals must be `react,react-dom,zod` only; externalizing `@json-render/*` leaves unresolvable `dist/chunk-*` imports.
- `ToolUse` props carry `output` (the stored result) and `isRunning`. `e.viewport.columns` is in every render event, not in `tool.call`.

## Global Constraints

- No build step, no `package.json`, no `node_modules` in occam. Tests: `node --test tests/*.test.js`.
- The page fetches only library code: CDN hosts `esm.sh`, `cdn.jsdelivr.net`, and Google Fonts for a token font. A CSP `<meta>` sets `connect-src 'none'`.
- Every CDN URL names an exact version (list above).
- The mod module has no DOM and no Node APIs: `$.fs`, `$.process`, `$.env`, `$.settings` only.
- `Image` source is `{ png: base64 }`, at most 2 MiB decoded.
- Draw only when `isRunning` is false and `output` holds an image block.
- Tool name `lens` → `mcp__occam__lens`, `isDeferred` left default (deferred).
- agent-browser session name: `lens-<first 8 chars of session id>`. Closed at `session.end`.
- Picture geometry: `COL_PX = 8` CSS px per column, `CELL_ASPECT = 2.1` (cell height / width), `MAX_COLS = 160`, `MAX_ROWS = 40`, gutter 4 columns, device scale factor 2, fallback 1 when the PNG is over 2 MiB.
- Version 1.29.0 → 1.30.0 (minor: new skill) in three places; CHANGELOG entry.

## Review Focus

1. Source that breaks the page (bad spec key, unknown component, Mermaid syntax error) → the tool returns the errors as text and still returns whatever drew; never a hang. Test: `parseBatch` with an error list; page fixture with a syntax error in Task 3.
2. Source text holding `</script>` or `<!--` → the page still parses. Test: `buildPage` escapes `<` in the JSON slot.
3. Content taller than `MAX_ROWS` → the result says `clipped: true` so Claude splits it. Test: `rowsFor` caps at 40; page fixture in Task 3.
4. A terminal that cannot draw pictures (env var missing, VS Code, desktop) → the result says `not shown inline` with the fix. Test: `inlineReason` table.
5. Two Claude sessions render at once → separate browser sessions. Test: `sessionName` differs per id.

### Task 2: Pure core

**Files:**

- Test: `tests/lens-core.test.js` (imports `../hooks/lens-core.mts` with dynamic `import()` in a `before` hook; Node's `node:test` file stays CJS like the others)

**Interfaces — Produces** (all pure, named exports):
- `KINDS = ['spec', 'html', 'mermaid']`
- `parseInput(raw: unknown): { kind, source: string, alt: string, tokens: string } | { error: string }` — `kind` in KINDS; `source` non-empty string (a `spec` source may also arrive as an object: stringify it); `alt` non-empty string ≤ 200 chars; `tokens` optional CSS string, default `''`.
- `buildPage(template: string, { kind, source, theme, tokens, width, maxHeight }): string` — replaces `/*LENS_CONFIG*/null` with `JSON.stringify({kind, source, theme, width, maxHeight})` where every `<` becomes `<`; replaces `/*LENS_TOKENS*/` with `tokens`; for `html` also replaces `<!--LENS_HTML-->` with `source`.
- `layout(columns: number | undefined): { cols: number, width: number, maxHeight: number }` — `cols = clamp((columns ?? 104) - 4, 40, MAX_COLS)`, `width = cols * COL_PX`, `maxHeight = Math.round(MAX_ROWS * COL_PX * CELL_ASPECT)`.
- `rowsFor(cols: number, pxW: number, pxH: number): number` — `clamp(Math.round(cols * pxH / pxW / CELL_ASPECT), 1, MAX_ROWS)`.
- `pngSize(base64: string): { width, height }` — IHDR big-endian u32 at byte 16 and 20.
- `inlineReason({ force, termProgram, term }): string | null` — `null` when `force === '1'`, `termProgram === 'ghostty'`, or `term === 'xterm-kitty'`; else `'not shown inline: this terminal is not known to draw pictures. Run /lens --setup.'` Mark: `razor: known-terminal list, read an engine capability flag when one exists`.
- `resolveTheme(setting: string | undefined, appleStyle: string): 'light' | 'dark'` — setting starting with `dark` → dark; starting with `light` → light; else `appleStyle.trim() === 'Dark'` → dark, else light.
- `sessionName(sessionId: string): string` — `'lens-' + sessionId.slice(0, 8)`.
- `batchCommands({ width, scale, theme, url, png }): string[][]` — exactly, in order: `['set','viewport',String(width + 32),'900',String(scale)]`, `['set','media',theme]`, `['open',url]`, `['wait','--fn','document.documentElement.dataset.lens']`, `['eval','JSON.stringify(window.__lens)']`, `['screenshot','#lens',png]`.

### Task 3: Page template

**Files:**
- Create: `skills/lens/page.html`
- Create: `skills/lens/fixtures/` — `card-chart.json` (spec), `layout.html`, `flow.mmd`, `broken.json` (unknown component + bad prop)

**Interfaces:**
- Consumes: the slots `buildPage` fills: `/*LENS_CONFIG*/null`, `/*LENS_TOKENS*/`, `<!--LENS_HTML-->`.
- Produces: a page that sets `document.documentElement.dataset.lens = 'ready'` when drawn (also after an error), and `window.__lens = { errors: string[], clipped: boolean }`; the picture is the element `#lens`.

Page contract (the implementer writes the code):
- `<meta http-equiv="Content-Security-Policy">`: `default-src 'none'; script-src 'unsafe-inline' https://esm.sh https://cdn.jsdelivr.net; style-src 'unsafe-inline' https://fonts.googleapis.com; font-src https://fonts.gstatic.com data:; img-src data: blob:; connect-src 'none'`. Check in Step 2 that esm.sh module fetches pass under it; widen only `script-src` if they do not.
- Import map from the planning spike (versions in Tech Stack; `?external=react,react-dom,zod` on every json-render and Recharts URL; `react/`, `react-dom/`, `zod/` prefix entries). Mermaid: `https://esm.sh/mermaid@12.3.0`.
- `<style type="text/tailwindcss">`: shadcn's stock `:root` and `.dark` variables including `--chart-1`…`--chart-5`, the `@theme inline` map, `@custom-variant dark`, `* { @apply border-border }`, then `/*LENS_TOKENS*/` last so repo tokens win.
- `<html>` gets class `dark` when `config.theme === 'dark'`. `#lens` has `width: config.width px`, `max-height: config.maxHeight px`, `overflow: hidden`, padding 16px, background `var(--background)`.
- Error capture before any import: `window.error`, `unhandledrejection`, and a `console.error` wrapper push into `__lens.errors`.
- `spec`: `defineCatalog(schema, { components: { ...shadcnComponentDefinitions, BarChart, LineChart, AreaChart, PieChart }, actions: {} })`, `defineRegistry`, then `JSONUIProvider` + `Renderer`. Chart props (zod): `{ data: Array<Record<string, string|number>>, x: string, series: Array<{ key: string, label?: string }>, height?: number (default 280), stacked?: boolean }`. Colors `var(--chart-N)` by series index. `isAnimationActive={false}` on every series. Charts written with `React.createElement`, no JSX. A spec that is not valid JSON → error, no render.
- `mermaid`: `mermaid.initialize({ startOnLoad: false, theme: dark ? 'dark' : 'default', fontFamily: getComputedStyle(body).fontFamily })`, `mermaid.render('m', source)` into `#lens`.
- `html`: the source sits in `#lens` at build time; its own scripts run.
- Ready: after render, `await document.fonts.ready`, two `requestAnimationFrame`s, set `clipped = lens.scrollHeight > lens.clientHeight`, then `dataset.lens = 'ready'`. Any thrown error also ends in `ready`.

### Task 4: The mod module

**Files:**
- Create: `hooks/lens.tsx` (replaces the probe `hooks/lens.ts`; delete that file)
- Modify: `hooks/hooks.json` → `"modules": ["./lens.tsx"]`
- Test: `hooks/lens.test.tsx` (run with `claude plugin test .`)

**Interfaces:**
- Consumes: every export of `./lens-core.mts` (Task 2); `skills/lens/page.html` at `${$.plugin.root}/skills/lens/page.html` (Task 3).
- Produces: tool `mcp__occam__lens`, input `{ kind: 'spec'|'html'|'mermaid', source: string|object, alt: string, tokens?: string }`; result `[{ type:'text', text }, { type:'image', source:{ type:'base64', media_type:'image/png', data } }]`. `text` lines: `shown inline` or the `inlineReason` line; `clipped: true|false`; `errors:` then one line each, or `errors: none`.

Behaviour:
- `session.start`: `$.tool.register({ name: 'lens', description, inputSchema })`. Description, ≤ 3 sentences: what it draws, the three kinds, "Read the lens skill first."
- `ui.render` on `{ component: 'ToolUse' }`: for every call of this tool, store `e.viewport?.columns` in a module variable `lastColumns` (it runs while input streams, before `tool.call`). Draw only when `!e.props.isRunning`, `Array.isArray(e.props.output)`, an image block is in it, and `$.ui.resolve(e).Image` exists: `<Box flexDirection="column">{await next(e)}<Image source={{ png: data }} columns={cols} rows={rowsFor(cols, w, h)} alt={input.alt} /></Box>` with `cols = layout(e.viewport?.columns).cols` and `w,h = pngSize(data)`. Else `next(e)`.
- `tool.call` on `{ tool: 'mcp__occam__lens' }`: `parseInput` → on error return `{ deny: error }`. Theme: `resolveTheme(await $.settings.read({ key: 'theme' }), stdout of ['defaults','read','-g','AppleInterfaceStyle'])` (non-zero exit = light). Dir `${TMPDIR}/occam-lens/<sessionName>/`; write `<n>.html` with `buildPage`; run `['agent-browser','--session',name,'batch','--json']` with `stdin` = JSON of `batchCommands`, `timeoutMs: 60000`. Read the PNG with `$.fs.read(png, { as: 'bytes' })`; when the base64 decodes past 2 MiB, run again with scale 1. A missing `agent-browser` binary → `{ deny: 'agent-browser not found. Run /lens --setup.' }`.
- `session.end`: `agent-browser --session <name> close`, then `rm -rf` the session dir. Both best-effort.
